# 观众站点签到（AudiencesSignIn）

MoviePilot **V3** 插件：自动完成观众（Audiences）等 NexusPHP 站点的每日签到。

## 工作原理

**签到入口是站点顶部用户栏**（每个页面右上角都能看到的用户信息栏最右侧）。
点击那里的「签到」即原地完成签到 —— **不跳页、不弹窗**。

站点顶部栏的两种状态（实测）：

| 状态 | 顶部栏渲染 |
| --- | --- |
| **未签到** | `<a class="site-userbar__compact-tool">签到</a>` ← 可点，插件要点的就是它 |
| **已签到** | `<span class="site-userbar__compact-tool--attended">已签到 +32</span>` ← 非可点元素 |

因此插件采用两段式：

```
HTTP 探测站点首页 index.php
   ├─ 已签到        → 直接结束（不启动浏览器，成本最低）
   ├─ Cookie 失效   → 失败并提示更新站点 Cookie
   ├─ 尚未签到      → 启动浏览器（unsigned）
   └─ 被 CF 质询    → 启动浏览器
                        ├─ 先写入 Cookie 罐 + 对齐 UA（决定登录态是否成立）
                        ├─ 打开首页 → **主动点击顶部栏的「签到」**
                        ├─ 点击后立即校验（最多约 4 秒，命中即提前返回）
                        └─ 未命中则继续轮询等待
                             ├─ 顶部栏变成「已签到 +32」→ 签到成功（附带奖励）
                             └─ 超时 → 失败，按提示改模式或加长等待
```

浏览器调用走宿主稳定 SDK `app.sdk.browser.launch_browser_context`，插件不自建 Playwright 适配器。

### ⭐ 签到入口在顶部用户栏，不在签到页（v1.5.3 修正的方向性错误）

前几版一直加载 `attendance.php`，然后在**签到页内部**找签到按钮。方向从一开始就偏了：

> **`attendance.php` 本身不产生签到行为。** 它只是"签到状态展示页"，
> 在里面怎么点、怎么等都不会有结果。

用户实测澄清：
> 他在右上角的签到点一下（顶部用户信息栏那里），自动就完成了。
> 不需要在签到页里点任何东西，也不跳页、不弹窗。

所以 v1.5.3 把加载页从 `attendance.php` 改为**站点首页 `index.php`** ——
顶部栏是全站组件，首页必然完整渲染，也最贴近真人操作路径。

#### ⚠️ 顶部栏里的"兄弟陷阱"

签到按钮和「收件箱 / 发件箱」在**同一个容器**里，而且 **CSS class 完全相同**：

```html
<div class="site-userbar__compact-actions">
  <div class="site-userbar__compact-action-group">
    <a class="site-userbar__compact-tool" href="attendance.php">签到</a>   <!-- 要点这个 -->
    <a class="site-userbar__compact-tool" href="messages.php">收件箱</a>   <!-- class 一模一样！ -->
    <a class="site-userbar__compact-tool" href="messages.php?box=-1">发件箱</a>
  </div>
</div>
```

→ 因此**绝不能"取容器内第一个可点元素"**（那会点到收件箱），
必须**按「签到」语义筛选**（文本含"签到"或 `href` 含 `attend`）。

另一个坑：旧版判断"这个元素是不是已签到标签"时用了 `innerText`，
它会把**整条用户栏的文字**都读进来 —— 于是"签到"被邻近的"已签到"污染，
导致真正的签到按钮被误判成"已签到"而跳过。v1.5.3 改为只读元素**自身的直接文本节点**。

### 登录态为什么容易丢（v1.4.0 修复的根因）

浏览器能否"以登录身份"打开页面，取决于三件事，缺一不可：

| 环节 | 说明 | 宿主行为 |
| --- | --- | --- |
| **Cookie 送达** | 站点会话 Cookie 必须真正进入浏览器 | `launch_browser_context(**kwargs)` 把参数**原样透传**给 CloakBrowser；实测该版本**不接受 `cookies`**，抛 `TypeError` → 登录态丢失 |
| **写入时机** | 必须在导航**之前**写入浏览器 cookie 罐 | `page.set_extra_http_headers` 只影响后续请求头，对已发起的验证挑战无效 |
| **UA 一致** | NexusPHP 会话 Cookie 与 `cf_clearance` **都绑定 UA** | 浏览器用自带指纹 UA 访问、Cookie 却是用站点登记的 UA 申请的 → 服务端判会话无效 |

三者任一不满足，症状**都表现为"一直卡在人机验证页"**，极易被误判成"验证码过不去"。
v1.4.0 的处理：cookie 改由 `context.add_cookies()` 在导航前写入 cookie 罐；
UA 默认跟随站点登记值；并新增 UA 一致性核对告警。

### 关键词判定为什么要加登录态反证（v1.5.0 修复的根因）

v1.4.0 实跑后登录态已成功生效（日志里能看到用户名、分享率、上传量），
但插件仍然报"60s 内人机验证未通过"。原因是 `NEED_VERIFY_MARKERS` 里的
「人机验证」「验证通过后将自动完成签到」「完成人机验证即可」是站点页面上的**静态说明文案**，
只要页面渲染出来就可能被读到 —— 用它单独判定，就会把**已经签到成功的页面**误判成"需要验证"。

v1.5.0 的修正：判定"真的需要人机验证"必须**同时满足**两个条件：

| 条件 | 含义 |
| --- | --- |
| 正文含验证类文案 | 页面上确实出现了相关字样 |
| **且** 正文不含任何"已签到"标记 | 排除"已签到 + 页面上有静态文案"的组合 |
| **且** 正文不含任何登录用户信息（分享率 / 收件箱 / 控制面板 等） | 排除"会话有效"的场景 —— 已登录用户不可能被要求人机验证 |

另外把页面文本读取顺序改为**优先整份 HTML**（`content()`）再退回可见文本（`inner_text`），
避免无头模式下因窗口尺寸导致底部内容被判为不可见、从而读到不稳定的文本。

### HTML 转纯文本为什么必须先删注释（v1.5.1 修复的根因）

v1.5.0 实跑出现了一个更隐蔽的症状：HTTP 200，但**四组判定词一个都没命中**，
状态直接变成 `unknown`，0.6 秒就结束，连浏览器都没启动。

关键线索在日志的正文片段，它**以一堆注释残余符开头**：

```
正文片段：Audiences :: 签到 - Powered by NexusPHP --> --> --> --> --> ... &#8249; 上一页 &#8250; 下一页 &#）
```

而此前实跑的正文片段开头是干净的「首 页 论 坛 影 视…」。
**同一个站点、同一个接口，转出来的文本开头不一致** —— 问题出在解析，不在站点。

根因：v1.5.0 用的正则 `re.sub(r"<[^>]+>", " ", html)` 在遇到 HTML 注释时
会**在第一个 `>` 处提前截断**。注释里本来就可能含 `>` 字符（`-->`、`=>`、`a > b`），
于是产生两个后果：

| 后果 | 说明 |
| --- | --- |
| 注释残余符留在正文 | `-->` 之类的碎片进入文本，污染关键词匹配 |
| 注释**内部文字**被当正文 | `<!-- ... -->` 里的内容被保留下来，可能带来假的命中或干扰 |

v1.5.1 的修正：**先删除注释（含内部文字），再剥标签**。

```python
text = re.sub(r"(?is)<!--.*?-->", " ", html)          # 先删注释
text = re.sub(r"(?is)<script.*?</script>", " ", text)
text = re.sub(r"(?is)<style.*?</style>", " ", text)
text = re.sub(r"(?s)<[^>]*>", " ", text)              # 再剥标签
text = re.sub(r"(?m)&[a-zA-Z#0-9]{1,8};", " ", text)  # 清理实体（含界面箭头）
text = re.sub(r"(?:\s*-->\s*)+", " ", text)           # 兜底：清理残留注释尾
```

**通用教训**：剥 HTML 标签的正则**永远不能当作"能读懂注释"**。
凡是把 HTML 转纯文本再拿去做关键词判定的场景，删注释这一步不能省。

### 「兜底」为什么会变成"内鬼"（v1.5.2 删除兜底的根因）

v1.5.1 曾加入一条防御性兜底：

> 登录态正常 **且** 页面没有任何未签到标记 → 判为"今日已签到"

它的前提是「未签到时页面**一定**出现人机验证文案」。
**这个前提被站点改版推翻了** —— 现在的人机验证是
**「点击签到按钮之后才弹出」**的：

```
未签到态页面 → 没有任何验证文案
             → 但登录信息（收件箱 / 发件箱 / 控制面板）一应俱全
             → 兜底条件被满足
             → 未签到被静默判成"已签到"
             → 直接跳过签到动作，什么都没做
```

用户实跑的证据非常直接：插件日志报「✅ 今日已签到」，
而**同一时刻去站点点签到，却显示刚签到成功**。

**教训（比这个 bug 本身更重要）**：

> 兜底逻辑一旦**长期命中**，它就不再是兜底，而是**主逻辑**。
> 当站点改版破坏它的前提时，它不会报错，只会安静地把错误结论汇报成成功。

所以 v1.5.2 的原则改为 **宁可 `unknown`（可观测、会提醒），不要 `signed`（静默放过）**：

| 选择 | 若实际"已签到" | 若实际"未签到" |
| --- | --- | --- |
| 报 `unknown`（现行） | 多一句提醒，用户一看便知 | **会去执行签到** ✅ |
| 报 `signed`（旧兜底） | 正确 | **静默漏签，且日志还显示成功** ❌ |

判断"是否已签到"现在只认**明确的证据**（见下节），不再靠推断。

### 为什么判定要分"结构"和"文案"两路（v1.5.2）

v1.5.1 打算「改用 CSS class 判定」，但仍然失败了 —— 因为把 class 串
也塞进了 `_to_text()` 的**纯文本**里查，而标签已经被剥掉了：

```python
# 纯文本长这样（class 名早已消失）
"每日签到 今日已签到，明天再来吧 今天已签到 您今天已经签到过了，请勿重复刷新。"

# 所以在纯文本里查这个永远失败：
"attendance-card--done" in text   # → 永远 False
```

v1.5.2 新增 `_match_signed()`，**分三路判定**：

| 路 | 查什么 | 查哪里 | 例 |
| --- | --- | --- | --- |
| ① 结构标记 | CSS class 名 | **HTML 原文** | `attendance-card--done`、`attendance-page--success` |
| ② 文案标记 | 中文文案 | **纯文本** | `今天已签到`、`请勿重复刷新`、`签到成功` |
| ③ 正则模式 | 带数值的渲染 | **纯文本** | `已签到 +32`、`本次获得 +32` |

**站点三态实测基线**（2026-09-14 本地实跑抓取线上页面）：

| 状态 | 结构标记 | 文案 |
| --- | --- | --- |
| 已签到 | `attendance-card--done`<br>`site-userbar__compact-tool--attended` | 今天已签到 / 今日已签到，明天再来吧 / 请勿重复刷新 |
| 签到成功 | `attendance-page--success`<br>`attendance-card--success` | 签到成功 / 本次获得爆米花 |
| **未签到** | 只有 `attendance-page`（**无修饰符**） | 有签到按钮 |

> ⚠️ `attendance-page` 是**基类，三态都有**，绝不能单独拿它判断已签到。

### 为什么必须"点"而不是"等"（v1.5.2 最关键的行为修正）

旧版本加载签到页后的行为是 **只轮询、不点击**：

```python
page.goto(target_url, ...)
while time.time() < deadline:
    if "已签到" in text: return "success"   # 干等页面自己变化
```

在 v1.1.0 时代这没问题 —— 当时验证是随页面加载自动触发的。
但站点改版后流程变成了：

```
打开首页 → 点击顶部用户栏的「签到」 → 自动弹出人机验证 → 验证通过 → 原地显示「已签到 +32」
```

**不点那个入口，验证永远不会开始**，于是只能一路等到超时。

v1.5.2 新增 `_click_sign_button()`（v1.5.3 重写策略顺序），在加载后**主动点击**。
识别策略按优先级排列（**先精确后模糊**）：

| 优先级 | 策略 | 说明 |
| --- | --- | --- |
| **0** | **顶部用户栏内的「签到」元素** | **实测确认的真实入口**，必须优先；带语义筛选（文本含"签到"或 `href` 含 `attend`） |
| 1 | `href` / `class` / `id` 含 `attend` | 全局兜底 |
| 2 | 文本含「签到 / 打卡 / 领取」 | 全局兜底 |
| 3 | 签到卡片区块内的可点元素 | 最后兜底（站点若改回页内签到仍可用） |

所有策略都**排除已签到标记**（`--attended` class 或自身文本含「已签到」），避免误点状态徽章。
点击后**立即校验**（最多约 4 秒）：顶部栏签到是原地生效的，命中即提前返回，不必干等满等待时长。
若已点击但迟迟没结果，**12 秒后补点一次**（应对首次点击落空或弹层遮挡）。

> 排障时若日志报「未找到签到按钮」，日志会同时打印
> **用户栏内所有可点元素的文本**（如 `['签到', '收件箱', '发件箱']`），
> 一眼就能看出是站点改文案了，还是容器选错了。

## 功能

| 功能 | 说明 |
| --- | --- |
| 复用站点 Cookie | 直接读取 MoviePilot「站点管理」中已配置站点的 Cookie 与 User-Agent，无需重复粘贴 |
| 两段式签到 | 先 HTTP 探测，必要时才动用浏览器，兼顾速度与成功率 |
| 浏览器模式 | 自动（先无头，失败改有头）/ 仅无头 / 仅有头 |
| 定时签到 | 通过 cron 表达式设置签到时间（默认每天 08:00） |
| **一键立即运行** | 设置页的 **「立即运行一次」** 按钮（v1.2.0 新增），当场执行并弹出结果 |
| 手动签到 | 远程命令 `/audiences_signin`、插件 API `/run` |
| 结构化日志 | 分节 + 结论先行：执行头 / 每站分步 / 每站结论 / 结尾总览，一眼判断是否正常（v1.2.0 新增） |
| **页面证据日志** | 首次判定与超时时记录浏览器页面的**地址 / 标题 / 命中关键词 / 正文片段**，并打印**命中词前后文**（v1.3.0 引入，v1.5.0 增强） |
| **登录态保障** | 导航前把 Cookie 写入浏览器 cookie 罐、UA 默认对齐站点登记值，并对 UA 不一致主动告警（v1.4.0 新增） |
| **判定防误报** | 验证类文案必须配合"无登录信息"才成立，避免把已签到的成功页误判为需验证（v1.5.0 新增） |
| **安全解析 HTML** | 转纯文本时先删注释再剥标签；界面箭头等实体一并清理（v1.5.1 新增） |
| **诊断友好** | 探测未识别时打印正文长度/HTML 长度/前段/中段/尾段；`/state?full=1` 可拿全文（v1.5.1 新增） |
| **主动点击签到** | 加载后**自动点击顶部用户栏的「签到」**触发人机验证（旧版只干等，永远等不到）——四级识别策略（**顶部用户栏优先**），排除已签到徽章防误点，点击后立即校验，未命中则 12 秒后补点一次（v1.5.2 引入，v1.5.3 重写策略） |
| **结构 + 文案双路判定** | 结构标记（CSS class）查 **HTML 原文**、文案标记查 **纯文本**、正则匹配带数值的渲染如「已签到 +32」（v1.5.2 新增） |
| **未签到态可识别** | `unsigned` 状态，判定依据是**顶部栏存在签到入口**（而非"加载的是不是签到页"），据此执行签到而不是误报已签到（v1.5.2 引入，v1.5.3 更新依据） |
| **加载首页而非签到页** | 签到入口是全局顶部栏，加载 `index.php` 最贴近真人操作；历史配置的 `attendance.php` 会自动纠正（v1.5.3 修正） |
| 状态探测 | 插件 API `/state`：只用 HTTP 探测状态，不签到、不起浏览器 |
| 结果通知 | 可选发送通知，失败时附带失败原因 |
| 历史记录 | 保留最近 20 条签到记录，可在插件详情页查看 |
| 当天跳过 | 当天已签到成功时自动跳过，避免重复请求 |
| 多站点 | 「签到站点域名」支持英文逗号分隔多个 NexusPHP 站点 |

## 安装

把本仓库添加为 MoviePilot 插件仓库后安装，步骤见仓库根目录 `README.md`。

## 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 启用后定时任务才会注册 |
| 发送签到通知 | 开 | 使用 MoviePilot 消息渠道发送结果 |
| 当天已成功则跳过 | 开 | 避免同一天重复签到 |
| 失败重试次数 | 1 | 网络抖动时的重试次数 |
| 签到站点域名 | `audiences.me` | 多个站点用英文逗号分隔 |
| 签到时间（cron） | `0 8 * * *` | 5 段 cron，例如 `0 1 * * *` 表示每天 01:00 |
| 签到入口页路径 | `index.php` | 签到按钮在站点**顶部用户栏**，加载首页即可点到；一般无需修改（填 `attendance.php` 会被自动纠正为 `index.php`） |
| 允许调用浏览器过人机验证 | 开 | 关掉则未签到时无法完成签到 |
| 浏览器模式 | `auto` | 自动（先无头，失败改有头）/ `headless` / `headed` |
| 等待验证完成秒数 | `60` | 从打开页面起最长等待时间（点击后会先做一次约 4 秒的快速校验） |
| **强制用站点登记的 UA 打开浏览器** | 开 | **推荐开启**。NexusPHP 会话 Cookie 与 `cf_clearance` 都绑定 UA，浏览器自带指纹 UA 与登记 UA 不一致时，会话会被判无效，表现为一直卡在人机验证页（v1.4.0 新增） |
| Cookie 覆盖（可选） | 空 | 留空即使用站点管理中的 Cookie |
| User-Agent 覆盖（可选） | 空 | 留空即使用站点管理中的 UA |

## 签到结果含义

| 结果 | 含义 | 处理建议 |
| --- | --- | --- |
| 签到成功（无头/有头浏览器） | 浏览器通过了人机验证，站点已记账，尽量附带奖励 | 无需处理 |
| 今天已经签到过了 | 站点提示重复签到 | 无需处理 |
| Cookie 已失效 | 页面为登录页或提示需要登录 | 到「站点管理」更新该站点 Cookie |
| 被 Cloudflare 质询拦截 | Cookie 缺 `cf_clearance` 且浏览器未过 | 更新 Cookie（建议 CookieCloud），或改用仅有头模式 |
| 人机验证未通过 | 等待超时 | 先看日志里的**页面证据行**（地址/标题/关键词/片段）判断浏览器实际落到了哪个页面：<br>· 若地址/标题指向 `challenge-platform`、`Just a moment` → 是 Cloudflare 质询，重点更新 Cookie；<br>· 若日志里出现**「某人机验证词」上下文**且上下文含用户名 / 分享率 → 说明是**静态文案误命中**（v1.5.0 起已自动排除）；<br>· 若确实停在验证页 → 检查是否出现 **UA 不一致** 告警，开启「强制用站点登记的 UA 打开浏览器」；再考虑改用「仅有头」模式或把等待秒数加到 120；<br>· 若像登录页 → Cookie 失效 |
| 日志出现「UA 不一致」告警 | 浏览器指纹 UA ≠ 站点登记 UA，会话被判无效 | 到设置页开启「强制用站点登记的 UA 打开浏览器」 |
| 日志出现「人机验证」但页面显示已签到 | v1.4.0 及更早版本的**静态文案误判** | 升级到 v1.5.0 或更高（判定已加登录态反证） |
| 浏览器启动时提示"拒绝了 cookies 启动参数" | 宿主当前版本不接受该启动参数 | 正常现象（v1.4.0 起已自动改用 cookie 罐注入登录态，该行提示仍会保留以便排查） |
| 浏览器执行异常 | 宿主浏览器能力不可用 | 确认站点设置里「浏览器仿真」为 `playwright` |
| **结果无法识别 / 正文片段以 `-->` 开头** | v1.5.0 及更早版本的**HTML 注释解析缺陷**：正则被注释里的 `>` 提前截断 | 升级到 v1.5.1（转为纯文本前已先删注释） |
| **日志报「今日已签到」但实际没签到** | v1.5.1 及更早版本的**有害兜底**：未签到态页面同样有登录信息、且改版后不再有验证文案，导致兜底条件被满足 | **升级到 v1.5.2 或更高**（该兜底已删除，未签到态现在会判 `unsigned` 并去执行签到） |
| **浏览器起了、页面正常，但始终等不到签到成功** | v1.5.2 及更早版本**在错误的页面找按钮**：签到入口在顶部用户栏，而不在签到页内部，`attendance.php` 本身不产生签到行为 | **升级到 v1.5.3**（改为加载首页 + 优先点顶部栏入口） |
| 日志出现「判定：今日尚未签到（顶部栏有签到入口）」 | **正常**：插件正确识别出需要签到 | 无需处理。若紧接着报「已点击签到按钮」后成功即为正常流程 |
| 日志出现「未能点到签到按钮」 | 站点改版导致按钮识别策略失配 | 日志会同时打印**用户栏内所有可点元素的文本**；请连同未签到态页面 HTML（`Ctrl+U` 复制）一起反馈，以便补充策略 |
| 日志出现「结果无法识别（已是最新版）」 | 站点改了文案或结构 | 看新日志里的**正文长度 / 中段 / 尾段**定位；也可访问 `/state?full=1` 取页面纯文本全文，据此补充关键词（见下） |

## 判定词的维护方式

判定逻辑集中在文件顶部的数组常量，便于按站点扩展：

| 常量 | 查哪里 | 内容 |
| --- | --- | --- |
| `SIGNED_STRUCTURE_MARKERS` | **HTML 原文** | 已签到的 CSS class 名（`attendance-card--done`、`site-userbar__compact-tool--attended` 等） |
| `SIGNED_MARKERS` | **纯文本** | 已签到文案（`今天已签到`、`请勿重复刷新`、`签到成功` 等） |
| `SIGNED_REGEX_MARKERS` | **纯文本** | 带数值的渲染模式（`已签到 +32`、`本次获得 +32`） |
| `ATTENDANCE_PAGE_MARKER` | **HTML 原文** | 签到页基类（`attendance-page`），`_looks_like_unsigned` 的兼容路 |
| `DEFAULT_SIGNIN_PATH` | — | 加载页默认值 `index.php`（签到入口在全局顶部栏） |
| `SIGNIN_BUTTON_SELECTORS` | **HTML 原文** | 顶部用户栏容器选择器（**排障参照用**，实际选择器内联在页面内 JS 里，改动需两处同步） |
| `NEED_VERIFY_MARKERS` | 纯文本 | 人机验证文案（**必须配合登录态反证**使用） |
| `LOGGED_IN_MARKERS` | 纯文本 | 登录用户信息（收件箱 / 发件箱 / 控制面板 等） |
| `LOGIN_MARKERS` / `CF_MARKERS` | 纯文本 | 登录失效与 Cloudflare 质询特征 |

**五条教训**（都来自真实误报/漏判）：

1. 不要把「获得」这类词写进成功判定。本站签到页**常驻**「首次签到获得 20 粒爆米花」，
   只要该词在成功关键词里，就会在任何情况下都误报签到成功。
2. **不要把静态说明文案当作状态判定的唯一依据**。「人机验证」等词在已签到的页面上
   依然可能出现，必须配合"页面不含登录用户信息"才成立。
3. **剥 HTML 标签前必须先删注释**。`>` 是注释正文里的常客（`-->`、`=>`、`a > b`），
   朴素正则会在第一个 `>` 处截断，既留下碎片污染匹配，又把注释内部文字当正文保留 ——
   v1.5.0 的 `unknown` 就是这么来的。
4. **class 名只能查 HTML 原文，不能查剥完标签的纯文本**。v1.5.1 就是在这里栽的 ——
   想用更稳的 class 判定，却把它放进了纯文本里查，结果那些串永远匹配不到。
   **判定依据越"结构化"，越要盯住它的载体格式**。
5. **先确认"那个动作发生了吗"，再设计"等待"**。v1.5.2 修好了"点击"却点在了错的页面上
   （签到入口在顶部栏，不在签到页）：`attendance.php` 本身不产生签到行为，
   在里面怎么等都不会有结果。**写轮询前先回答：这个状态变化需要我触发哪个动作、在哪个元素上？**

**排障口诀**：
- 先怀疑**解析**，再怀疑**文案**。日志正文片段出现 `-->`、`<![endif]` 之类残留 → 解析问题。
- 正文干净但没命中 → 才是站点文案变了。
- **判定"什么都没匹配到"时，先确认自己查的是不是对的载体**（HTML 还是纯文本）。
- **浏览器起了、页面也正常，但永远等不到结果 → 先怀疑"点错了地方"，而不是"验证过不去"**。

## 版本

- **v1.5.3**：**找到真正的签到入口 —— 站点顶部用户栏**。用户实测澄清「在右上角的签到点一下（顶部用户信息栏那里），自动就完成了，不需要在签到页里点任何东西，也不跳页、不弹窗」—— 这推翻了前几版的根本假设：签到入口**不在 `attendance.php`**，而在**全站顶部用户栏**。前几版一直加载签到页然后在页内找按钮，方向从一开始就偏了：`attendance.php` 本身不产生签到行为，在里面怎么点、怎么等都不会有结果。<br>本版改动：<br>① 加载页从 `attendance.php` 改为**站点首页 `index.php`**（顶部栏必然完整渲染，也最贴近真人操作；历史配置里的 `attendance.php` 会自动纠正为 `index.php`）；<br>② `_click_sign_button` **重写策略顺序**，新增最高优先级的「顶部用户栏签到元素」策略 —— 实测发现签到按钮与「收件箱 / 发件箱」是**兄弟节点且 CSS class 完全相同**，因此必须按「签到」语义筛选，**绝不能取容器内第一个可点元素**（那会点到收件箱）；<br>③ **收紧已签到元素排除逻辑**：旧版用 `innerText` 读整条用户栏，会让「签到」被邻近的「已签到」污染而误判，改为只读元素**自身直接文本**并检查 `--attended` class；<br>④ 点击后**立即校验**（最多约 4 秒）：顶部栏签到是原地生效的，命中即提前返回成功，不必干等满等待时长；<br>⑤ 未签到的正向证据改为「**顶部栏存在签到入口**」（新增 `_looks_like_unsigned`），不再依赖"加载的是不是签到页"，同时保留对 `attendance.php` 的兼容。<br>另：未找到按钮时日志会打印**用户栏内所有可点元素的文本**，便于一眼判断是站点改文案还是容器选错。
